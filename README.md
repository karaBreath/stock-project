  ⚔️ สงคราม · 💧 พลังงาน · % เงินเฟ้อ · 🚢 การค้า · ▣ ชิป · 📊 ตลาดหุ้น ·
  🦠 โรคระบาด · 📄 ผลประกอบการ · 📍 ข่าวไทย
  (ไอคอนเป็น SVG ฝังในไฟล์ ไม่ต้องโหลดจากเน็ต · ไอคอนที่อยู่ด้านหลังโลกจะจางหายอัตโนมัติ
  และมีระยะห่างขั้นต่ำ 14° กันไอคอนซ้อนทับกัน)

### เครื่องเรียนรู้ (เมนู "เครื่องเรียนรู้")

เฝ้าดู **ข่าวทั่วโลก + ราคาหุ้น + ปัจจัยมหภาค** พร้อมกัน แล้วหาว่าอะไรสัมพันธ์กัน

**วิธีคิด**
- แปลงข่าวเป็น time series รายวัน (Tone) และราคาเป็นผลตอบแทนรายวัน %
- จับคู่ตามวันที่ แล้วหา correlation ที่ **lag** ต่าง ๆ
  - `lag = 0` → ข่าววันนี้สัมพันธ์กับราคาวันนี้ (เกิดพร้อมกัน)
  - `lag = 1+` → **ข่าววันนี้ "นำ" ราคาอีก N วัน** ← อันนี้แหละที่ใช้เทรดได้
- รายงาน `r` (ความแรง), `n` (จำนวนข้อมูล), `hit rate` (% ที่ทายถูก)

**ใช้ได้ตั้งแต่วันแรก** — GDELT ให้ timeline ย้อนหลังได้ถึง 1 ปี และ yfinance ให้ราคาย้อนหลังหลายปี
เครื่องจึงเรียนรู้จากอดีตได้ทันที ไม่ต้องรอสะสมข้อมูลเป็นเดือน

**ยิ่งเก็บยิ่งแม่น** — แอปเก็บ snapshot ของข่าว+ราคาลงตาราง `observations` อัตโนมัติทุกชั่วโมง
คลังข้อมูลจึงโตขึ้นเรื่อย ๆ (กดปุ่ม "เก็บข้อมูลเดี๋ยวนี้" เพื่อเก็บทันทีก็ได้)

```powershell
# ปิดการเก็บอัตโนมัติ / ปรับความถี่
$env:LEARN_AUTO = "0"          # ปิด (ค่าเริ่มต้น = 1)
$env:LEARN_INTERVAL = "3600"   # เก็บทุกกี่วินาที
$env:LEARN_WINDOW_DAYS = "180" # ช่วงข้อมูลที่ใช้วิเคราะห์
$env:LEARN_MIN_SAMPLES = "30"  # n ขั้นต่ำถึงจะเชื่อผล
```

> ⚠️ **ข้อควรระวังทางสถิติ** — correlation ไม่ใช่ causation

**ตัวกันผลบังเอิญ (สำคัญมาก)**

หุ้น 1 ตัวถูกทดสอบ **16 สัญญาณ × 5 lag = 80 คู่พร้อมกัน** ถ้าใช้เกณฑ์ปกติ (p<0.05)
จะมีคู่ที่ "ดูใช่" โผล่มาเพราะบังเอิญราว **4 คู่** ทั้งที่ไม่มีความสัมพันธ์จริงเลย

แอปจึงยกเกณฑ์ด้วย **Bonferroni correction** ตามจำนวนคู่ที่ทดสอบจริง:

| ข้อมูล | ทดสอบ 1 คู่ | ทดสอบ 80 คู่ |
|---|---|---|
| 120 วัน | \|r\| ≥ 0.18 | \|r\| ≥ **0.31** |
| 150 วัน | \|r\| ≥ 0.16 | \|r\| ≥ **0.28** |
| 250 วัน | \|r\| ≥ 0.12 | \|r\| ≥ **0.22** |

**ผลทดสอบจริง — ป้อนข้อมูลสุ่มล้วน 30 ชุด (ชุดละ 64 คู่สัญญาณ)**

| ด่าน | ผล |
|---|---|
| ด่าน 1 · Bonferroni | เล็ดลอดไป **3/30 ชุด (10%)** |
| ด่าน 2 · walk-forward | จับได้ทั้ง 3 ชุด ตีตราว่า **overfit** |
| **แนะนำให้เทรดตามสัญญาณลวง** | **0/30 ชุด** ✅ |

> ⚠️ ข้อเท็จจริงที่ต้องเข้าใจ: **Bonferroni ไม่ได้การันตีว่าจะเจอ 0 คู่เสมอ**
> มันแค่คุมโอกาสพลาดไว้ราว 5% ต่อการทดสอบ 1 ชุด — นี่คือเหตุผลที่ต้องมี
> **ด่านที่ 2 (walk-forward)** ซ้อนอยู่ ของปลอมที่รอดด่านแรกจะถูกจับตรงนี้แทน

ในตารางจะเห็น **✅ = เชื่อได้** / แถวจาง = "อาจบังเอิญ" และ **คะแนนรวมจะปรับเฉพาะคู่ที่ผ่านเกณฑ์เท่านั้น**

### 🔄 ปิดลูป: ความรู้ที่เรียนได้ → มีผลต่อคะแนนจริง

สิ่งที่เครื่องเรียนรู้ไม่ได้อยู่แค่ในหน้าตัวเอง แต่ **ไหลกลับเข้าคะแนนรวม 0-100**:

1. ดูความสัมพันธ์ที่เรียนไว้แล้วของหุ้นตัวนั้น (เฉพาะที่ `n` พอ, `|r| ≥ 0.15`, **`lag ≥ 1`**)
   — ใช้เฉพาะ `lag ≥ 1` เพราะต้องการสัญญาณที่ *นำ* ราคา ถ้า `lag = 0` คือขยับพร้อมกัน ทำนายอนาคตไม่ได้
2. เทียบกับ **สภาพข่าวโลกตอนนี้** (tone วันนี้เทียบค่าเฉลี่ย 7 วัน)
3. แปลงเป็นคะแนนปรับ **สูงสุด ±10 คะแนน** บวก/ลบจากคะแนนฐาน

ผลที่เห็นในแอป:
- **หน้าวิเคราะห์** → แถบ "🧠 ข่าวโลกหนุน/กดดัน" พร้อมเหตุผลว่ามาจากความสัมพันธ์ไหน และ `ฐาน 62 → รวม 65`
- **รายงานประจำวัน** → การ์ด "🌍 ข่าวโลกที่ผิดปกติที่สุดวันนี้" + "🧠 หุ้นที่ข่าวโลกกำลังหนุน/กดดัน"

> **ถ้ายังไม่ได้เรียนรู้หุ้นตัวนั้น → ปรับ 0 คะแนน** คะแนนเท่าเดิมทุกประการ ไม่มีอะไรเปลี่ยนแบบเงียบ ๆ
> กดปุ่ม **"เรียนรู้ทั้ง watchlist"** ในเมนูเครื่องเรียนรู้ เพื่อเริ่มใช้งานทีเดียวทั้งพอร์ต

### 🧪 Backtest สัญญาณข่าว (เมนู "เครื่องเรียนรู้" → ปุ่มทดสอบย้อนหลัง)

ตอบคำถามว่า **"ถ้าเทรดตามสัญญาณข่าวจริง ๆ จะได้กำไรไหม"**

> ⚠️ **กับดักที่ทำให้ backtest ส่วนใหญ่โกหก** — ถ้าหาความสัมพันธ์จากข้อมูล 1 ปี
> แล้วเอา *ปีเดียวกันนั้น* มาทดสอบ ผลจะสวยเสมอ เพราะเลือกสัญญาณที่ fit กับข้อมูลชุดนั้นมาแล้ว

แอปจึงใช้ **walk-forward / out-of-sample**:

```
|<-------- ช่วงเรียนรู้ (60%) -------->|<---- ช่วงทดสอบ (40%) ---->|
 หาสัญญาณ + คำนวณเกณฑ์เข้าซื้อ ที่นี่      เทรดตามสัญญาณที่นี่เท่านั้น
```

- เกณฑ์เข้าซื้อ (tercile threshold) คำนวณจาก train เท่านั้น — กัน look-ahead
- หักค่าธรรมเนียม + สลิปเพจ **0.1% ต่อขา** ทุกไม้
- เทียบกับ **ซื้อแล้วถือ** ในช่วงเดียวกัน
- แสดงทั้ง in-sample และ out-of-sample เคียงกัน ให้เห็นว่าตัวแรกสวยกว่าเสมอ

**ตรวจจับ overfitting อัตโนมัติ** — ถ้าผลตอบแทนหรือความแม่นหล่นแรงจากช่วงเรียนรู้
มาช่วงทดสอบ จะขึ้น ⚠️ *"สัญญาณนี้ fit กับอดีตมากกว่าจะใช้ได้จริง — อย่าเอาไปใช้ตัดสินใจ"*
**ก่อน** ตัวเลขกำไรสวย ๆ เสมอ

ถ้าไม่เจอสัญญาณที่แรงพอ จะตอบว่า *"ไม่มีอะไรให้เทรด"* ซึ่งเป็นผลลัพธ์ที่ดี — ดีกว่าเทรดตามสัญญาณลวง

- ดูตลาด **ไทย** → SET, บาท/ดอลลาร์, ทอง, น้ำมัน

## 🤖 เชื่อมกับระบบเทรด MT5 ที่บ้าน (เมนู "พอร์ต MT5")

NEBULA กับ **volume-edge** (ระบบเทรดหุ้น US สาย Volume Profile ที่รันคู่กับ MT5)
เก่งคนละอย่างและไม่ทับกันเลย:

| volume-edge (ที่บ้าน + MT5) | NEBULA (คลาวด์ 24 ชม.) |
|---|---|
| ไม้จริงที่เปิดอยู่ · เหตุผลเข้าไม้ (ไทย) · journal | ข่าวโลก GDELT + เครื่องเรียนรู้ |
| Volume Profile · setup VAB/VAR · คุมความเสี่ยง | บทเรียนวิกฤต 25 ปี · แล็บกลยุทธ์ |
| ยิงออเดอร์จริง | เปิดจากไอแพดได้ทุกที่ |

**จุดที่ทำให้ 1+1 มากกว่า 2:** เอา *ไม้ที่ถืออยู่จริง* มาผ่าน *เครื่องอ่านข่าวโลก* ของ NEBULA
→ ตารางไม้เปิดจะมีคอลัมน์ **"ข่าวโลกตอนนี้"** บอกว่าข่าวกำลังหนุนหรือกดดันไม้นั้น
พร้อมเหตุผลที่ผ่านเกณฑ์สถิติแล้ว (เช่น *ข่าวพลังงานดีขึ้น → หนุน XOM อีก 2 วัน r=0.41 n=150*)

หน้านี้ยังโชว์: สถานะ MT5/ตลาด/ปุ่มหยุดฉุกเฉิน · สรุปบัญชี · สถิติจริงต่อ setup
จากไม้ที่ปิดแล้ว · และ**สัญญาณล่าสุดรวมที่ "ไม่ซื้อ" พร้อมเหตุผล**

### วิธีเชื่อม (ตั้ง 2 ค่าใน Render → Settings → Environment)

```
VE_BASE_URL = https://<ที่อยู่เว็บระบบเทรดของคุณ>
VE_AUTH_KEY = <ค่าเดียวกับ AUTH_KEY ใน .env ของ volume-edge>
```

ไม่ตั้ง = ปิดฟีเจอร์เงียบ ๆ ไม่กระทบส่วนอื่น · เครื่องที่บ้านปิดอยู่ก็ไม่พัง แค่ขึ้นว่าต่อไม่ได้

🔒 **ความปลอดภัย**: สะพานนี้ยิงเฉพาะคำสั่งอ่าน (GET) — มีเทสบังคับว่าห้ามมี
`requests.post/put/delete` ในไฟล์นี้เด็ดขาด และฝั่ง volume-edge เองก็ล็อกว่า
จากภายนอกเป็นโหมดดูอย่างเดียวอยู่แล้ว **สั่งซื้อขายข้ามระบบไม่ได้**

## 🌐 ข้อจำกัดจริงของ GDELT (วัดเอง ไม่ได้เดา)

ยิงทดสอบตรงไปที่ `api.gdeltproject.org` จากเครื่องกลาง 3 รอบ ได้ข้อเท็จจริงนี้:

| สิ่งที่ทดสอบ | ผลจริง |
|---|---|
| `api/v2/geo/geo` (GEO 2.0) | **HTTP 404 ทุกแบบ 6 ครั้ง** — GDELT ปิด API นี้แล้ว |
| `TimelineTone` 30d / 90d / 3m | ✅ HTTP 200 |
| `TimelineTone` 100d ขึ้นไป (120d/180d/365d/540d/18m) | ❌ HTTP 429 "query too large" |
| `startdatetime`/`enddatetime` ช่วง 90 วันในอดีต | ✅ HTTP 200 พร้อมข้อมูลของช่วงนั้นจริง |
| คำขอทั่วไป | ถูกปฏิเสธ (429) บ่อยมาก แม้พารามิเตอร์ถูกต้อง |

**แอปจึงออกแบบตามนี้:**

- **ลูกโลก** ไม่ใช้ GEO ที่ตายแล้ว — ดึง `ArtList` แล้วนับข่าวตาม **ประเทศต้นทาง**
  (`sourcecountry`) วางจุดที่พิกัดกลางของประเทศนั้น (`services/country_geo.py`)
- **ทะลุเพดาน 90 วัน** ด้วยการ **แบ่งยิงทีละช่วง 85 วันย้อนหลังแล้วเก็บสะสม**
  ช่วงที่ได้แล้วเก็บไว้ 60 วัน (ข้อมูลอดีตไม่เปลี่ยน) · คำขอหนึ่งดึงใหม่ไม่เกิน 2 ช่วง
  ผู้ใช้จึงไม่ต้องรอ และคลังจะ **ยาวขึ้นเรื่อย ๆ เอง** ทุกชั่วโมงที่แอปรัน
- **กันโดนปฏิเสธ**: เว้นจังหวะทุกคำขอ · ถอยหลายชั้นเมื่อล้ม · พัก 45 วินาทีเมื่อโดน 429 ซ้ำ

## 🩺 ตรวจระบบ (เมนู "ตรวจระบบ")

มี rate limit และบางตัวใช้ไม่ได้ในบางประเทศ **ถ้าไม่มีตัวตรวจ เวลาพังจะเห็นแค่
"ไม่มีข้อมูล" โดยไม่รู้ว่าพังตรงไหน**

หน้านี้ยิงทดสอบทีละแหล่งแล้วรายงานว่า ต่อได้ไหม · ใช้เวลากี่ ms ·
**ข้อมูลที่ได้กลับมาหน้าตาเป็นยังไง** (คีย์อะไรบ้าง ตัวอย่างค่า) · ถ้าพัง พังเพราะอะไร

ตรวจครอบคลุม: ไลบรารีที่ต้องมี · GDELT ทั้ง 4 endpoint (รวมทดสอบว่ารับ
`timespan=540d` ไหม) · Yahoo ราคาไทย/สหรัฐ/ETF · `period=max` สำหรับหน้าวิกฤต ·
สัญลักษณ์มหภาคทุกตัว · ฐานข้อมูล · การตั้งค่า

- การจับคู่ข่าวกับราคาต้องนับเป็น**วันทำการ** ไม่ใช่วันปฏิทิน (บั๊กที่เคยเจอจริง)
- เครื่องเรียนรู้ต้องจับ lag ที่ฝังไว้ได้ และไม่จับของที่ไม่มี
- Bonferroni ต้องเข้มขึ้นเมื่อทดสอบหลายคู่
- catalyst ต้องคัด `lag=0` / `r` อ่อน / `n` น้อย ออก และไม่ปรับเกิน ±10
- backtest ต้องจับสัญญาณที่ "เคยจริงแต่หายไป" ได้
- ช่วง train กับ test ต้องไม่ทับกัน (กันโกงด้วยการดูอนาคต)
- crisis ต้องวัด drawdown/recovery ถูก และไม่รายงานตัวเลขทั้งที่ไม่มีข้อมูล
- แล็บกลยุทธ์: เครื่องจำลองคิดค่าธรรมเนียมถูกเป๊ะ (คำนวณมือเทียบ) ·
  โมเมนตัม/เทรนด์ห้ามดูอนาคต และต้องหนีตลาดขาลงที่ปลูกไว้ได้ ·
  ข่าวพุ่งต้องจับ drift ที่ปลูกไว้ได้และไม่เทรดมั่วตอนข่าวเงียบ · league จัดอันดับตรงไปตรงมา
